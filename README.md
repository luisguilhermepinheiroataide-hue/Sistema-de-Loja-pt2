Sistema de Gerenciamento de Estoque

Desenvolvido inicialmente por Arthur Tabbi e Gabriela Oliveira

O sistema StockFlow consiste em uma aplicação de gerenciamento de estoque desenvolvida na linguagem Java com suporte de persistência de dados no banco de dados relacional PostgreSQL. O propósito principal do projeto é demonstrar a aplicação prática dos conceitos fundamentais da programação orientada a objetos associados a padrões de arquitetura corporativa e engenharia de software de alto nível, tornando-o um modelo estruturado para avaliação acadêmica.

Entre os padrões de projeto aplicados na construção do sistema, destaca-se o Singleton na classe de conexão com o banco de dados. Essa implementação garante a existência de uma única instância ativa para gerenciar as operações do driver, o que otimiza o uso de recursos do servidor e previne falhas críticas de vazamento de conexões. Complementarmente, a camada de persistência utiliza o padrão Data Access Object isolado por meio de interfaces. A separação estrita entre a interface e sua implementação concreta assegura o desacoplamento do código, permitindo que a lógica de negócios permaneça independente dos detalhes de infraestrutura da tecnologia de banco de dados escolhida.

No coração do sistema está o modelo de domínio representado pela entidade de produto. Esta classe não atua como um mero repositório anêmico de dados, mas carrega o encapsulamento de regras de negócio essenciais, tais como os métodos de entrada e saída de mercadorias, que validam a integridade e o estado do saldo de estoque antes que qualquer modificação seja enviada para a persistência. O controle de fluxo e a robustez do software são reforçados pelo tratamento estruturado de exceções e pelo uso de blocos que realizam o fechamento automático de recursos como conexões e declarações SQL, evitando sobrecarga no ambiente de execução.

A arquitetura do sistema divide-se em quatro pacotes bem definidos para organizar as responsabilidades do código de maneira limpa. O pacote de conexão abriga a lógica de inicialização do driver JDBC, enquanto o pacote de entidades lida exclusivamente com os conceitos e comportamentos do negócio. O pacote de acesso aos dados executa as instruções do CRUD através de comandos SQL padronizados e, por fim, o pacote de aplicação serve como o ponto de entrada do sistema para coordenar as rotinas principais e simular as transações em tempo de execução.

Para a configuração da infraestrutura, o script de banco de dados cria a estrutura necessária por meio de comandos para gerar o banco de dados denominado StockFlow e a tabela de produtos com identificadores autoincrementáveis. A execução da classe principal valida a integração correta de todas as camadas do sistema, exibindo mensagens detalhadas no console que confirmam o sucesso da conexão, da inserção do registro, da listagem dos dados salvos e da atualização dos itens em conformidade com as regras de negócio estabelecidas.
